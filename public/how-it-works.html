01
CARRIER IMAGE UPLOAD
You provide a cover image — PNG or BMP. This is the "right side up" world. The image is drawn onto an HTML5 Canvas which exposes raw RGBA pixel data as a flat byte array. Every pixel has 4 channels: Red, Green, Blue, Alpha.
canvas.getImageData() → Uint8Array [R,G,B,A, ...]
1920×1080 image = 8.2M bytes of raw pixel data
02
SECRET SERIALIZATION
Your secret file is read as raw bytes. A header is prepended with a magic signature, filename length, filename, and data length. This ensures perfect reconstruction during decode, preserving the original format and name.
Header: SHDW (4B) + name_len (4B) + filename + data_len (4B)
Max capacity = width × height × 3 / 8 bytes
03
PASSWORD-SEEDED PRNG
Your password is hashed using FNV-1a into a 32-bit seed. That seed initialises a Mulberry32 PRNG, which performs a Fisher-Yates shuffle over all pixel indices — producing a unique, deterministic scramble only reproducible with the exact password.
FNV-1a(password) → 32-bit seed → Mulberry32(seed)
Fisher-Yates over N pixels → unique pixel order[]
04
LSB ENCODING
Each bit of the payload is written into the Least Significant Bit of an R, G, or B channel of a pixel selected by the PRNG order. Changing only the LSB shifts a colour value by at most ±1 — completely imperceptible to the human eye.
pixel[i] = (pixel[i] & 0xFE) | bit
255 → 254 or 255  ·  visual change: < 0.4%
05
LOSSLESS PNG EXPORT
The modified pixel array is written back to the canvas and exported as PNG — a lossless format that preserves every pixel exactly. JPEG must never be used: its lossy compression would corrupt the LSB bits entirely.
canvas.toBlob('image/png') → lossless stego image
Visual difference: undetectable
PIXEL MAPPING
Glowing pixels have been modified by LSB encoding. The corner bit shows what was injected.
🔐
SECURITY MODEL
Shadow Fold provides steganographic security. The password controls which pixels carry the data via PRNG — without it, the data is unreadable even if its presence is suspected.
